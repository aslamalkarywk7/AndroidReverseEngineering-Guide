# Contributing

Thanks for helping improve this Android reverse engineering guide.

## How to propose guide improvements

1. Fork the repository and create a short-lived branch for your change.
2. Keep edits focused: fix one topic per pull request when possible.
3. Match the existing Markdown style (headings, fenced code blocks with language tags).
4. Verify commands, tool names, and links before submitting.
5. Only analyze apps you own or are explicitly authorized to test; do not submit proprietary app code, credentials, or personal data.
6. Open a pull request describing what you changed and why.

Small fixes (typos, broken links, outdated tool versions) are welcome without opening an issue first. For larger additions, please open an issue describing the proposed section first.
